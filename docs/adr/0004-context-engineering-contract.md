# ADR-0004: 上下文工程契约——四段组装、缓存断点与压缩策略

- **Status**: Accepted
- **Date**: 2026-08-24

## Context

仓库此前没有上下文组装约定。两个天然张力:对话消息 append-only 对 prompt cache
最友好,而状态类内容每轮变化;裁剪省 token 但破坏缓存前缀。本契约参照
《深入理解 AI Agent》ch2 校准(缓存三条铁律、压缩六策略实验 2-10、滑动窗口
批判实验 2-3)。

## Decision

### 组装顺序(自缓存稳定到易变)

```
[全局静态前缀: 唯一 system prompt + 工具定义]   ← 所有用户逐字节相同,跨会话共享缓存
─── cache 断点 1 ───
[会话稳定块: 身份/角色/当前周期]                ← 会话内不变,第 2 轮起命中
[轨迹: 对话消息,append-only]                    ← 只增不改
[易变块: 代码维护的状态栏,user 角色消息挂末尾]   ← 每轮尾部替换,失效范围仅自身
─── cache 断点 2(可选) ───
```

- **system prompt 全局唯一变体**:角色/身份一律进断点后的稳定块,绝不烘进
  system prompt——断点前每多一个运行时条件,缓存键变体翻倍(2^N 组合)。
- **易变块选「尾部替换」而非「持久追加」**(Claude Code `<system-reminder>` 是
  持久追加):状态栏位于轨迹末尾,删旧加新的失效范围只有自己;会话 <40 轮时
  持久追加只会积累陈旧状态。持久追加留作长会话备选。
- **状态栏必须代码维护**(从图状态确定性派生),绝不交给模型批量统计。

### 裁剪与压缩

- 阈值前不动(招新对话大多 <40 轮)。
- 超阈值后**批量上下文感知摘要**;禁止滑动窗口与按长度硬切(实验 2-3:滑窗
  破坏前缀缓存且丢关键工具结果,Agent 陷入重复调用循环;实验 2-10:非任务感知
  压缩是六策略最差档)。
- 摘要提示词携带当前查询意图与上下文;固定保留清单:[决策、约束、失败路径、引用]。
- 摘要用 strong 模型(「压缩即理解」,压缩模块能力需接近主模型)。
- **压缩熔断器**:连续 N 次压缩失败即停,降级并上报人工。
- **实现惰性**:契约现在冻结;实现等真实长会话出现(触发指标:单会话 >40 轮
  成为常态)。

### Prompt 版本化

一图一节点一文件(`prompts/<graph>/<node>.md`),frontmatter 记
`version / model_tier / cache_prefix`;代码零 prompt 字符串;改 prompt 必跑
钉住该版本的 eval。

### 模型路由(GRA-08)

默认 strong:用户可见输出 / 评估评分 / 批判 / 面试题 / LLM-as-judge / 摘要压缩。
降 light 仅限内部模式化步骤(字段抽取;意图分类若复活),且须 eval 证明不掉分。
脱敏、投影裁剪等永远用代码不用模型。

## Consequences

- `prompts/` 目录组织由本 ADR 固定;GRA-07(摘要压缩)从实现 issue 降级为
  「已设计、按触发指标实现」。
- 若未来引入子 Agent:继承缓存需与父级逐字节对齐,替换字符串首次出现即冻结
  ——届时另立决策。
