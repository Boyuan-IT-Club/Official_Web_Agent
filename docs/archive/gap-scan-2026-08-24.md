## 一、缺口分组(多个调研方向独立命中同一区域,去重合并)

### 会话管理缺口 · thread/会话生命周期是全架构最大空白 【P0】
- 同 thread 并发消息无串行化(飞书连发两条→checkpointer 冲突/确认令牌错配)
- SSE「确认/拒绝」上行端点不存在——ADR-0005 令牌机制在官网/CLI 侧无载体;拒绝后续流协议未定义
- thread_id 命名规则/属主校验缺失(CLI `--session dev` 与官网 SSE 同 thread 互踩;可枚举=PII 泄露)
- SSE 断线重连/心跳/nginx 长连接调优:**暂缓**(项目所有者 2026-08-24,M5 前再定);「确认上行端点」不暂缓,仍属 M5 必做。
- C 的 thread 切分(面试官×场次 vs 候选人)未定,三态机/卡片/速记隔离全悬空
→ 全部挂在 M3(飞书)/M5(官网)主线上,上线即撞。

### 隐私边界缺口 · PII 边界只覆盖「进模型前」一个点 【P0·红线级】
- **trace 记录脱敏前原始 PII**:get_resume_detail 返回完整简历,脱敏节点在其后;OBS-01 全图上报 + ADR-0006「trace 全量」→ 原始 PII 直落 Langfuse
- 输出侧无守卫:模型生成的面试题/报告可能复述简历里的手机号/QQ
- 占位符映射契约缺失:存哪/是否确定性/还原白名单——影子运行对不上、面试题可能泄漏占位符
- checkpointer 里 interrupt 挂起载荷(含姓名/时间/原因)TTL 与 SEC-06 留存无对齐
- 跨年查重(EVA-10)依赖被脱敏抹掉的身份键,且"往年摘要库"是未声明的 PII 仓库
- 速记比简历更敏感(面试官主观评价),留存策略未含

### 评分流水线账本缺口 · B 的数据面几乎全空,且压在「后端谈判」单点 【P0】
- 草稿/评审端点 openapi 不存在;PUT /score 只收 int,维度分+依据无落库通道
- 分数卡 schema 无定义:量规版本/prompt 版本不绑定评分→第 2 周改量规后分数不可比
- 评审确认机制零设计:发行方/批量指纹/一次性/拒绝流/抽查 vs 全量矛盾
- 批处理幂等与运行状态:checkpointer 是对话 thread 语义,B 批跑没有 thread;重跑=覆盖已修正分?
- 影子运行(EVA-09,M2 验收)ground truth 数据源未定
- EVA 产物存飞书多维表格 vs C 宿主在 admin 前端,形态冲突
