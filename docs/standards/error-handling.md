# 错误处理规范

> **何时读**：写任何**会失败**的代码时——I/O、外部调用、入参校验、状态机分支。
> **一句话**：错误要么被明确处理，要么带着上下文向上抛；**禁兜底**——静默失败是最贵的 bug。

## 错误三类（先分类再选处理方式）

| 类 | 例 | 处理 |
|---|---|---|
| **业务错误**（预期内） | 校验失败、余额不足、资源不存在 | 领域错误类型或返回值；消息面向调用者可理解 |
| **系统错误**（预期外但必然偶发） | 网络、DB、超时 | 抛异常带上下文（目标/入参摘要/原始错误），由上层决定重试或失败 |
| **编程错误**（不该发生） | 断言失败、不变量被破坏 | fail fast 立即崩；不 catch、不修复现场，修的是代码 |

## 分层传播（翻译只发生在边界，对齐 layering.md）

- **基础设施层**：把低级错误（SQL/HTTP）**包装**成带上下文的自定义错误再上抛；禁裸抛驱动/框架错误穿透。
- **领域层**：只认/抛领域错误；不知道 HTTP/SQL 存在。
- **应用层**：**决定命运**——重试、降级、汇总、放弃（编排是它的职责）；把领域错误翻译成用例结果。
- **接口层**：翻译成对外契约（统一错误码 + 消息结构、正确的 HTTP status）；**内部细节不出边界**（SQL、堆栈、内部路径禁进响应）。

## 外部调用与网络

- **超时必设**：任何网络调用没有超时 = 定时炸弹；默认值也要显式写出来。
- **重试三问**（答齐才许加重试）：操作幂等吗？这类错误可重试吗（超时/5xx 可，4xx 不可）？有退避与上限吗？
- 失败必留痕：每次失败 WARN/ERROR（见 [observability.md](observability.md)），禁静默吞。

## 红线（项目硬约定，重申）

1. **禁兜底**：不用默认值/降级/推断掩盖失败——失败就该喊出来，报警比静默便宜。确需降级（fail-open）属于**设计决策**：注释里写清为什么吞掉是安全的、降级后系统处于什么状态（参见工作区 CLAUDE.md「该写」一节）。
2. 空 catch 必须注释为什么（[comments.md](comments.md)），且必须有替代处理（log 或 rethrow 二选一）。
3. **校验在边界**：外部输入（API 入参、用户输入、文件内容、LLM 产出）在接口层用 schema 校验（Pydantic/Zod）后才进业务；内层信任已校验的类型。
4. 对外 API 统一错误形状：错误码 + 消息结构一处定义，禁各 route 自行发挥；异常文本不得直通客户端。

## 检验问句

- 这行 I/O 失败了，调用方拿到的错误能定位到根因吗（哪个目标、什么错、哪个 request_id）？
- 这个 catch 块吞掉的错误，明天出了事查得到吗？查不到 = 不许吞。
